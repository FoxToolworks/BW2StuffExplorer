# Version 0.5 Stage 4 — Interface Completion

## Stage 4.1 scope

Stage 4.1 corrects window sizing and scroll behavior without changing archive parsing, classification, metadata or relationship results.

- Entry properties opens at 960 × 540 on its first use, with 700 × 450 minimum dimensions.
- A user-resized and moved properties window retains its bounds for the remainder of the application session.
- General, File details and References begin at their top-left origin when the window opens and whenever the selected tab changes.
- The main file grid begins at its top-left origin after a completed folder navigation or new search result is applied.
- Superseded debounced searches cannot apply either stale results or a stale scroll reset.
- Normal file-list columns use stable, user-resizable default widths with enough reserve for the vertical scrollbar and layout rounding.
- Horizontal scrolling remains automatic when the window is genuinely too narrow, a user widens columns, or recursive search exposes the Path column.

Sorting, grouping, multi-selection, row and column virtualization, recycling and read-only archive access remain unchanged.

## Stage 4.2 scope

Stage 4.2 improves the References table without changing any relationship or resolution result.

- Material index, role and resolution status use stable readable widths.
- The source/model column and resolved-target/stored-reference column divide remaining space proportionally.
- Truncated paths, candidate lists and statuses expose their complete value through a wrapped tooltip.
- Rows and headers use a consistent compact height.
- Columns remain user-resizable and reorderable, with automatic horizontal scrolling when minimum widths no longer fit.
- Reference rows retain row and column virtualization with recycling.

## Stage 4.2.1 scope

Stage 4.2.1 gives both relationship directions one permanent column order:

`Material index | Role | Model entry | Stored reference | Status | Resolved texture / candidates`

Every row is therefore self-contained and keeps the same meaning whether properties were opened from a BWM model or a DDS texture. Resolution evidence uses the compact labels `Exact`, `Unique`, `Not found` and `Ambiguous`; a wrapped tooltip preserves the full reason and explicitly limits filename lookup and not-found results to the opened archive. Frozen columns are removed so a genuinely overflowing table uses one conventional full-width horizontal scrollbar.

## Stage 4.3 scope

Stage 4.3 improves the File details reading hierarchy without changing provider results or factual values.

- Details are grouped into stable File, Image, Pixel format, Storage and Model sections where applicable.
- Each technical fact uses one consistent label/value row with a quiet label background.
- Values remain selectable and copyable, wrap within the available width and expose their complete text through a wrapped tooltip.
- Invalid and unsupported states remain in the File section with their original reason text.
- Formats only show sections for facts their provider actually supplied; no empty sections or inferred metadata are added.

## Stage 4.3.1 scope

Stage 4.3.1 applies the Stage 4.3 property surface to General without merging its responsibility with provider-specific details.

- General and File details use the same row template, label width, wrapping and complete-value tooltip behavior.
- Name, full path, type, modification time and size form the File section.
- Archive path and entry offset form the Archive section.
- Every displayed value and its formatting remain unchanged and selectable.
- The file header remains unchanged until a real Preview tab provides enough context for a final space and navigation decision.

## Stage 4.4 and 4.4.1 final scope

Stage 4.4 froze the Version 0.5 feature set for the final Windows verification pass. Stage 4.4.1 applies the accepted final presentation corrections.

- Project and About metadata identify the final build as Version 0.5.0; assembly and file versions remain 0.5.0.0.
- Source, XAML, resources, event bindings, documentation links and the complete 13-format real-archive inventory receive static consistency checks.
- The release checklist covers build, self-tests, archive loading, navigation, grouping, search, export, properties, DDS/BWM inspection, error handling and packaging.
- No new parser, provider, relationship rule, preview or icon family is added during the release freeze.
- The final presentation keeps the compact header and spacing, centralized `Details` label and consistent References selection behavior accepted in Stage 4.4.1.

Specialized metadata for CHA, ABN, CSK and other additional formats belongs to Version 0.6 providers, not the Version 0.5 interface-completion pass.
