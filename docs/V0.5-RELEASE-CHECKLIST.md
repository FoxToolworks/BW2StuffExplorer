# BW2 Stuff Explorer 0.5.0 — Release checklist

This checklist is the final Windows acceptance gate for Version 0.5. Record any functional defect before the public runtime package is created.

## 1. Build and automated checks

- [ ] Open `BW2StuffExplorer.sln` in Visual Studio 2022 or newer with the .NET 8 Windows Desktop workload.
- [ ] Select `Release` and build the complete solution with zero errors and zero warnings.
- [ ] Run `StuffCore.SelfTest`; all checks finish with `StuffCore self-test passed.`
- [ ] Start `BW2StuffExplorer` from the Release configuration and confirm About displays `BW2StuffExplorer 0.5.0`.

Command-line equivalent:

```powershell
dotnet build .\BW2StuffExplorer.sln -c Release
dotnet run --project .\tests\StuffCore.SelfTest\StuffCore.SelfTest.csproj -c Release
```

## 2. Archive loading and navigation

- [ ] Open `Everything.stuff` from the dialog.
- [ ] Open the same archive by drag and drop.
- [ ] The archive reports 3,928 entries and loads without a parsing error.
- [ ] Browse several deep folders and use Back, Forward, Up and breadcrumbs.
- [ ] Switch to a folder after scrolling a long list; the new list starts at the top-left.
- [ ] Refresh preserves the selected folder and produces the same contents.
- [ ] A deliberately invalid or truncated file produces a clear error and does not replace the currently open archive.

## 3. Search, sorting, grouping and large lists

- [ ] Search is recursive below the selected folder and displays the Path column for results from subfolders.
- [ ] Multi-character typing remains responsive; a single punctuation character does not rebuild an almost complete archive result.
- [ ] Clearing search restores direct-folder contents and resets the list to the top-left.
- [ ] Sort Name, Modified, Type, Size and Offset in both directions.
- [ ] Group by None, File type and Asset category.
- [ ] `Group by → File type` keeps all DDS entries under `Texture (DDS)`.
- [ ] Large grouped folders scroll smoothly without the old permanent horizontal scrollbar at normal window width.

## 4. Export and read-only safety

- [ ] Export one file and compare its size with the archived entry.
- [ ] Export multiple selected files and confirm their archive paths are preserved.
- [ ] Export one folder and then the complete archive to empty destinations.
- [ ] Repeat a multi-file export and verify the single overwrite confirmation appears.
- [ ] Cancel a large export; no incomplete `.bw2stuff-*.tmp` file remains.
- [ ] Close the application during an export and confirm cancellation completes safely.
- [ ] The source STUFF archive remains byte-identical and no import, replace or write action is exposed.

## 5. Properties — shared interface

- [ ] Properties first opens at 960 × 540 and respects the 700 × 450 minimum.
- [ ] Resizing and moving Properties is remembered for the current application session.
- [ ] General starts at the top and shows the File and Archive sections with every value selectable.
- [ ] Details starts at the top and uses the same label/value design and wrapped complete-value tooltips.
- [ ] References starts at the top-left, retains the permanent six-column order and allows column resize/reorder.
- [ ] Narrowing the window produces only genuine, contained scrolling.
- [ ] Escape and Close both dismiss the window normally.

## 6. DDS facts

- [ ] Test DXT1/BC1, DXT3/BC2 and DXT5/BC3 entries with plausible dimensions and mip counts.
- [ ] Legacy DDS reports `Color space: Unknown`; no sRGB/linear recommendation is invented.
- [ ] `Alpha-capable format` and `Non-opaque alpha data` remain separate facts.
- [ ] Confirm examples of non-opaque alpha `Yes`, `No` and `Not applicable` where available.
- [ ] A truncated or invalid DDS reports `Invalid` and a reason without crashing.
- [ ] A DDS used by several models shows every BWM relationship in the reverse References view.

## 7. BWM facts and relationships

- [ ] Valid version 5 and version 6 BWM entries report signature, magic, version, model type, materials and texture-reference count.
- [ ] Static and skinned models retain their distinct file types; invalid payloads remain `Unknown Model Data (BWM)`.
- [ ] BWM References shows material index, role, model entry, stored reference, compact status and resolved texture/candidates.
- [ ] Verify at least one `Exact`, `Unique`, `Not found` and `Ambiguous` relationship where the archive provides examples.
- [ ] Reverse DDS relationships use the same six-column order and never turn a candidate into a confirmed use.
- [ ] An invalid BWM does not invent metadata or references.

## 8. Neutral formats and final presentation review

- [ ] Open CHA, ABN, CSK, TGA and at least one additional unsupported format.
- [ ] General remains available; Details and References display neutral, truthful fallback messages.
- [ ] Inspect main-window and Properties spacing, clipping, focus, tooltips and scrollbars at normal and minimum sizes.
- [ ] Confirm the compact header, tab spacing and References selection match the accepted Stage 4.4.1 presentation.
- [ ] Record optional Designer-Foxi adjustments separately; do not mix a new parser or feature into the final release.

## 9. Final packaging gate

- [ ] Every required Windows check above is accepted.
- [x] Version metadata and About text identify final 0.5.0.
- [ ] Changelog and roadmap mark Version 0.5 complete.
- [ ] Create a source ZIP without `bin`, `obj` or `.vs`.
- [ ] Create a Windows runtime ZIP from the verified Release build without development-only files.
- [ ] Test both ZIP files after fresh extraction before publication.
